Design notes

Async FIFO and Gray-code clock-domain crossing

Published 2026-10-01

These notes walk through the async_fifo core — a dual-clock FIFO in synthesizable SystemVerilog for passing a data stream between two unrelated clocks. It is parameterized by DATA_W and DEPTH, uses a valid/ready handshake on both sides, and is the building block under the AXI-Stream async bridge.

Why the pointers are Gray-coded

The write side owns the write pointer, the read side owns the read pointer, and each side needs a copy of the other's pointer to compute full or empty. A binary counter can change several bits on one increment (0111 → 1000), and if a synchronizer samples during that transition it can capture any mix of old and new bits — a pointer value that never existed. Gray code changes exactly one bit per increment, so a sampled value is always either the old pointer or the new one. Either answer is safe; it only makes the flag a cycle or two late.

Each side keeps a binary pointer for addressing RAM and derives the Gray value from the next binary value, so the Gray register is updated in the same clock as the address:

assign wbin_n  = wbin + wen;
assign wgray_n = (wbin_n >> 1) ^ wbin_n;

This is also why DEPTH must be a power of two: the Gray sequence only wraps with a single-bit change when the counter wraps at a power of two. The core rejects other depths at elaboration.

Two-flop synchronizers

The read pointer is brought into the write clock (rgray_s1 → rgray_s2) and the write pointer into the read clock (wgray_s1 → wgray_s2) through two flops each. Both stages are marked (* async_reg = "true" *) so FPGA tools place them close together and treat them as synchronizers in reliability and CDC reports.

Full and empty with one extra pointer bit

Pointers are AW+1 bits wide, where AW = $clog2(DEPTH). The extra MSB counts wraps, so "same address, same wrap" is empty and "same address, one wrap apart" is full:

  • Empty (read domain): the next read Gray pointer equals the synchronized write Gray pointer.
  • Full (write domain): the next write Gray pointer equals the synchronized read Gray pointer with its two MSBs inverted. In Gray code, a half-cycle offset flips the top two bits rather than just the top one.

Both flags are registered but computed from the next pointer value, so a write or read is reflected on the very next clock with no extra cycle of lag. Because each side only sees a delayed copy of the other pointer, the flags are pessimistic: full may stay asserted a few cycles after space frees up, and empty may stay asserted a few cycles after data arrives. They are never optimistic, so the FIFO can't overflow or underflow.

First-word-fall-through output

The storage array has a registered read so it maps onto FPGA block RAM. A second output register (o_q) presents data with rvalid, giving first-word-fall-through behaviour: the consumer sees valid data without asking for it, and takes it with rready. The two-stage pipeline (mem_q, then o_q) prefetches on its own, so the consumer can take one word per clock.

End-to-end, a written word reaches rvalid 3 to 5 read clocks later: two for the pointer synchronizer, plus the RAM read and output stages, with the exact number depending on clock phase.

Fill level on the write side

wlevel_o gives the write side an estimate of occupancy, which helps with almost-full thresholds or flow control. It converts the synchronized read Gray pointer back to binary and subtracts it from the write pointer. Like the flags, it can over-report (the read pointer it sees is a little old) but never under-reports.

Reset

Each domain has its own synchronous, active-low reset (wrst_n, rrst_n). They should be asserted together. Resetting only one side leaves the other holding a pointer that no longer matches, and the flags will be wrong until both are reset. If the resets come from an asynchronous source, generate each one with a reset synchronizer in its own domain.

Timing constraints

Static timing analysis can't reason about paths between unrelated clocks, so the pointer crossings need explicit constraints. The recommended form constrains only the Gray-pointer paths into the first synchronizer stage, with a datapath-only maximum delay of about one destination clock period:

# AMD Vivado (XDC) — adjust instance paths to your hierarchy
set_max_delay -datapath_only -from [get_cells -hier *wgray_reg*] -to [get_cells -hier *wgray_s1_reg*] <rclk_period>
set_max_delay -datapath_only -from [get_cells -hier *rgray_reg*] -to [get_cells -hier *rgray_s1_reg*] <wclk_period>

A blanket set_false_path between the clocks also closes timing, but it lets the tool route the pointer bits with arbitrary skew. That can break the one-bit-at-a-time guarantee Gray coding depends on, so prefer set_max_delay. The RAM read path is registered in the read clock and needs no special constraint.

Verification

The self-checking testbench runs two instances at unrelated clock ratios: fast write into slow read (10 ns / 27 ns) and the reverse. Writes and reads use random valid and ready patterns. A scoreboard checks every word for order and integrity, and the test also confirms that full is actually reached and that no word is lost or duplicated. Writing while full or reading while empty is simply ignored by the RTL, so a misbehaving producer or consumer can’t corrupt the pointers.
