Reset synchronizers: asynchronous assert, synchronous release

Published 2026-10-01

These notes cover reset_sync, the library's basic reset synchronizer, and reset_ctrl, a reset controller built on the same idea that adds pulse stretching, fan-out and software control. Every clock domain in a design needs one of these between its reset source and its logic.

The problem is the release, not the assert

A reset usually comes from somewhere with no relationship to your clock: a push button, a PLL lock signal, a power-on detector, another clock domain. Asserting it at any moment is harmless, because every flop simply goes to its reset value. Releasing it is different. If reset deasserts close to a clock edge, it violates the flops' recovery and removal times, the reset equivalent of setup and hold. Some flops then leave reset on this clock edge and others on the next, and a state machine can start in a state that should be impossible.

The standard fix: assert asynchronously, release synchronously. The design enters reset immediately, even with no clock running, and leaves it on a clean clock edge that every flop sees together.

How reset_sync does it

(* async_reg = "true", shreg_extract = "no" *) logic [STAGES-1:0] sr;

always_ff @(posedge clk or posedge asserted)
  if (asserted) sr <= '0;                       // assert: immediate, no clock needed
  else          sr <= {sr[STAGES-2:0], 1'b1};    // release: shift a 1 through STAGES flops

assign rst_o = ACTIVE_LOW_OUT ? sr[STAGES-1] : ~sr[STAGES-1];

While the input reset is active, every stage is held clear and rst_o is asserted. When the input releases, a constant 1 shifts through the chain. The first flop may go metastable, because its asynchronous clear was just removed at an arbitrary time, but it has a full clock period to settle before the next stage samples it. rst_o deasserts exactly STAGES clocks later, synchronous to clk. The testbench checks that count exactly.

  • STAGES (default 2, minimum 2) trades release latency for mean time between failures. Use 3 for very fast clocks or high-reliability designs.
  • ACTIVE_LOW_IN / ACTIVE_LOW_OUT set each side's polarity independently, so a low-true board reset can drive high-true internal logic without an extra inverter stage.
  • async_reg tells Vivado to place the chain's flops close together and treat them as a synchronizer. shreg_extract = "no" stops it from packing the chain into an SRL shift register, which would defeat the purpose.

The fully synchronous option

ASYNC_ASSERT = 0 builds the same chain with a synchronous clear. Some ASIC flows and coding standards forbid asynchronous resets entirely, and some FPGA guidelines prefer synchronous resets so the tools can use the flops' synchronous set/reset pins. The trade-off: assertion now needs a running clock, and the input should be held for at least one clock and be free of glitches, since it drives the flops' clear directly.

Constraining it

The input path into the chain is asynchronous by design. Tell the timing tool so, and keep everything after the chain fully timed:

# Vivado (XDC): the external reset into the synchronizer is asynchronous
set_false_path -to [get_pins -hier -filter {NAME =~ *u_rst_sync*/sr_reg*/CLR}]
# rst_o is synchronous to clk: leave its recovery/removal checks in place

Adjust the instance name to your hierarchy (the pin is PRE instead of CLR if your synthesis maps the chain the other way). Don't put a false path on rst_o itself; its release timing is the whole point.

One synchronizer per clock domain

A synchronized reset is only synchronous to the clock that produced it. A design with an AXI clock, a video clock and a SerDes clock needs three synchronizers, each fed by the same raw reset and clocked by its own domain. That's also why the async FIFO asks for its write and read resets to be asserted together but synchronized separately.

When you need more: reset_ctrl

reset_ctrl wraps the same asynchronous-assert/synchronous-release chain (default STAGES = 3) with the features a real system reset usually needs:

  • Pulse stretching. The output stays asserted for at least HOLD clocks (default 16, programmable at register 0x04), so a short glitch on the input still produces a clean, full-length reset.
  • Replicated outputs. NUM_OUT separate synchronized copies (default 4) split the fan-out of a heavily loaded reset net, which helps timing on large designs.
  • Software reset and visibility. AXI4-Lite registers provide a self-clearing soft-reset bit (0x00), status with a sticky "reset event seen" flag (0x08, write-1-to-clear), and a reset event counter (0x0C).

Release takes STAGES + 1 clocks after the input deasserts, plus the hold time.

Cost

reset_sync is the cheapest core in the library: Yosys (synth_xilinx, 7-series) maps the default configuration to two flip-flops and no LUTs. reset_ctrl, with its register file, counters and four outputs, comes to about 460 LUTs and 705 flip-flops.
