CRC-32 in SystemVerilog: parameters, reflection and parallel bytes

Published 2026-10-01

These notes cover the crc32 core and the shared crc_core engine behind it, which also drives CRC-16 and CRC-8. With its default parameters, crc32 computes the CRC used by Ethernet (IEEE 802.3), zlib, gzip and PNG. Overriding a handful of parameters turns it into any other 32-bit CRC.

Five parameters describe any CRC

Most published CRC specifications follow the Rocksoft model, and the core uses the same parameter names, so a CRC catalogue entry maps straight onto it:

ParameterCRC-32 (default)Meaning
POLY32'h04C11DB7Generator polynomial, MSB-first form, without the implicit x32 term
INIT32'hFFFFFFFFRegister value at the start of a message (reloaded by init_i and reset)
REFIN1Feed each input byte LSB first
REFOUT1Bit-reverse the register before output
XOROUT32'hFFFFFFFFFinal XOR applied to the output

The standard way to confirm a configuration is the check value: the CRC of the ASCII string 123456789. For CRC-32 it is 0xCBF43926, and the testbench checks exactly that. Other 32-bit CRCs need only parameter overrides:

// CRC-32C (Castagnoli: iSCSI, SCTP, ext4) - check value 0xE3069283
crc32 #(.DATA_W(8), .POLY(32'h1EDC6F41)) u_crc32c ( ... );

// CRC-32/MPEG-2 - no reflection, no final XOR - check value 0x0376E6E7
crc32 #(.DATA_W(8), .REFIN(1'b0), .REFOUT(1'b0), .XOROUT(32'h0)) u_mpeg2 ( ... );

Why reflection exists

Ethernet and UARTs send each byte least-significant bit first, while the textbook CRC divides MSB first. "Reflected" CRCs process the bits in wire order. In crc_core, REFIN simply reverses each byte before it enters the shift loop, and REFOUT reverses the 32-bit register before the final XOR. Both are wiring; neither costs any logic.

From a bit-serial loop to an XOR tree

The core describes the CRC the obvious way: a function that shifts one byte through the register a bit at a time.

for (int i = 7; i >= 0; i--) begin
  fb = r[CRC_W-1] ^ bb[i];
  r  = {r[CRC_W-2:0], 1'b0};
  if (fb) r = r ^ POLY;
end

Because POLY is a constant, synthesis unrolls the loop and reduces it to a fixed network of XOR gates. Each output bit becomes the XOR of a few register and data bits. No hand-derived equations or generated tables are involved, so the RTL stays readable and works for any polynomial.

For wider buses, the core applies byte_step once per byte lane within a single clock: lane 0 (data_i[7:0]) first, then lane 1, and so on. With DATA_W = 32, a full word is absorbed every clock, which is how the core keeps up with a 32-bit AXI-Stream or a 10G-class datapath.

Partial last words

Messages rarely end on a word boundary. keep_i has one bit per byte lane, and lanes with keep_i low are skipped. Valid bytes must be contiguous from lane 0, the same convention as AXI-Stream tkeep, so a 7-byte message on a 32-bit bus is one full word followed by a word with keep_i = 4'b0111. The testbench feeds the check string both ways, byte by byte and as 32-bit words with a partial last word, and both must give 0xCBF43926.

Interface and latency

  • init_i reloads INIT at the start of each message. It takes priority over valid_i in the same clock.
  • crc_o updates one clock after each valid_i. Reflection and the final XOR are applied combinationally to the running register, so crc_o is always the finished CRC of everything absorbed so far. No separate "finish" step is needed.
  • Idle cycles (valid_i low) leave the register untouched, so the source can stall mid-message.

Timing and size

The logic depth grows with DATA_W: four chained byte steps make a deeper XOR network than one. For CRC-32, DATA_W = 8 comfortably meets 100 MHz on 7-series parts. At 32 bits per clock, check timing for your target, and consider a lower clock or a pipelined variant if it doesn't close. At the default byte-wide configuration, Yosys (synth_xilinx, 7-series) estimates about 100 LUTs and 64 flip-flops.

Verification

The testbench runs a byte-wide and a 32-bit-wide instance side by side. Both check the standard check value, then 300 random messages of random length are compared against a separate bit-serial reference model. The run covers init_i mid-stream and idle cycles between words.
